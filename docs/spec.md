**One line:** A lender's loan app for borrowers on phone and desktop: apply, send documents, accept the contract and follow the loan.

## Rationale

**Who it is for:** the borrowers of a registered credit provider (a lender running Polaris). A borrower applies for a loan, uploads their ID and their bank statement (the PDF from the bank; photos are refused because they can be edited), accepts or declines the contract, asks for the payout and follows what they owe. The lender's staff work in the web back office (the `polaris-web` shell, its own app idea), not here.

**What this repo is: a public Dart (Flutter) app shell.** It holds no feature code. It commits only the composition inputs:
- a root `composer.json`, which CI overwrites from the Protocol template `core/utils/flutter/composer/polaris.json` (polaris_sdk is the home SDK, with base, auth, users, wallet, comms, telemetry, processing, corporate, agent, desktop and hms);
- `.rokct/initiate.py`;
- `.rokct/config/app_type` = `polaris`, which is the name the Flutter template already has, so no rename is needed.

All of `lib/` is generated by compose and gitignored. Features are built in `polaris_sdk` (RokctAI/corporate `polaris/dart` for the app, `polaris/frappe` for the backend), never in this repo.

**Backend:** the lender's own site with the Polaris Frappe module (`core/utils/frappe/composer/polaris.json`). The app talks to it only through the gateway (`api.lending.*`). The same backend serves the web shell, and the two must stay in step: what Dart does, the web does (`corporate/polaris/docs/web-app.md`).

**Known gaps to close in the SDK, not here:**
- `polaris/dart/manifest.json` has `routes: []` and its `home_page` names `templates/pages/polaris/app_page.dart`, which does not exist. The loan flow is built (`presentation/pages/loans/loan_screen.dart`, the six-step application under `presentation/pages/application/`, real `HttpPolarisRepository` with demo fixtures), but as home SDK it needs a home page and routes that open it.
- The Polaris backend template composes no `erp` module, yet Company (the lender and its NCR licence) and Customer (the borrower) exist only there, so the backend cannot hold an application yet. This waits on Ray's decision about where Polaris runs.

**Fleet rules this must satisfy:** the shell tracks zero `lib/` files and never treats `composer.json` as the source of truth (SDK list changes go to the Protocol template). Feature SDKs import only `base_sdk` (ADR-005). Remixicon only, `tr_keys` for all UI text. The guided tour runs in demo mode and never calls a real backend. Client statements are personal data: synthetic fixtures only, never real statements in any repo.

**Done for v0:** compose green from the Protocol template. Open the app to a Polaris home page, register and sign in, apply in the steps the backend checks (affordability, ID and phone, consent), upload the ID and a bank statement PDF, see the application's status, and accept or decline the contract once it is approved. On desktop the same app runs as the Windows build.
